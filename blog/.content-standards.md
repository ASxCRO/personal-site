# Blog content standard

Use this checklist before adding a post to `blog/`.

## Publication bar

- Write only from direct hands-on experience, a reproducible example, or a clearly labelled research synthesis. Never imply a personal case study without one.
- Explain the problem, operating constraints, chosen approach, and meaningful trade-offs. A code dump is not an article.
- Test every command and code sample in a clean local environment. Include the runtime, package/API version, and assumptions needed to reproduce it.
- Support externally verifiable product and technical claims with 3–6 primary sources (official documentation, specifications, or project repositories).
- Include `lastVerified` in frontmatter for time-sensitive posts, and review or unpublish articles when products change materially.

## Scope and voice

- Prioritise .NET, Azure, DevOps, databases, and AI infrastructure that strengthen the portfolio.
- Publish in English unless Croatian materially serves the intended local audience.
- Use precise, evidence-based titles and descriptions. Do not use claims such as “master”, “deep dive”, or “production-ready” without demonstrated evidence.
- Protect employers and clients: anonymise systems, remove credentials and private data, and describe constraints without exposing confidential details.

## Required frontmatter

```yaml
title: "Specific, evidence-based title"
date: YYYY-MM-DD
description: "Concrete outcome and audience"
tags: [".NET", "Azure"]
author: "Antonio Supan"
lastVerified: YYYY-MM-DD
featured: false
```

Set `featured: true` only for the one article that should lead the blog index; the index otherwise sorts by descending publication date.
